error "abc" \

The backslash must be the **last character on the line**—no spaces after it.

**Both files are processed, and the USB-Blaster III rules still apply.** A differently named file does not replace the other file.

udev processes them alphabetically:

1. `90-altera.rules`
2. `90-intel-fpga.rules`

For your scenario:

- **USB-Blaster and II:** Identical permission and symlink rules are generally harmless duplication.
- **USB-Blaster III:** Its matching rules apply from whichever file contains them. Their absence from the other file does not cancel them.
- **Conflicting settings:** The assignment operator determines the result:

| Assignment | Effect |
|---|---|
| `MODE="0666"` | A later matching rule can replace it. |
| `MODE:="0666"` | Final assignment; later rules cannot change this value. |
| `SYMLINK+="..."` | Adds a symlink rather than replacing the existing list. |

These ordering and assignment rules are documented in the [udev manual](https://github.com/systemd/systemd/blob/main/man/udev.xml).

On this computer, I found only [90-intel-fpga.rules](/etc/udev/rules.d/90-intel-fpga.rules). It already includes a USB-Blaster III / DE23-Lite entry for `09fb:6022`, and its permission assignments use `MODE:="0666"`. There is currently no `90-altera.rules` at that location.

| Change | Purpose and practical effect |
|---|---|
| Explicitly assigned negative pins D1, F1, G2, J1 | Made both sides of each differential pair explicit. With `OBUFDS`, Vivado assigns the matching negative pin from the positive pin, so these assignments were redundant. [AMD support discussion](https://adaptivesupport.amd.com/s/question/0D52E00006hpZv2SAE/how-do-i-create-a-xdc-file-for-my-project?language=en_US) |
| Combined the `TMDS_33` assignments into one command | Reduced repetition. Same electrical settings; no functional benefit. |
| Added `set_false_path -from [get_ports rst_n]` | Excluded paths starting at the external reset from timing analysis. This **does affect timing analysis and potentially optimization**, unlike the formatting changes. [AMD documentation](https://docs.amd.com/r/en-US/ug835-vivado-tcl-commands/set_false_path) |

The reset exception was intended for the asynchronous reset entering the synchronizers. Its broad scope deserves separate consideration because this board wrapper also supports non-graphics labs.
