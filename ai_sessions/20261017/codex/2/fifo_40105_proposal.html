40105 FIFO: one operation per clock

Use the external clock directly. Capture requests and data on each rising edge; drive the 40105 strobes on the following falling edge. Consecutive pushes work in consecutive clock periods, and push and pop may both be asserted in a period.

No clock divider, phase sequencer or occupancy counter. The previous CD4017/CD4029 design has been replaced. The 40105 supplies the ready signals used for empty and full.

Capacity: native depth is 16 words. Two parallel FIFO chips give width=8, depth=16; one gives width=4, depth=16. The supplied RTL defaults to depth 10. Compare with that same source instantiated at depth 16; the ten-word limit is removed along with its counter.

Timing contract: this matches the FIFO transactions observed by rising-edge synchronous logic. The internal operation occurs at the falling edge, so data and flags settle in the low half of the same period. Their continuous waveforms are not identical to the RTL immediately after the rising edge. Use empty, full and read_data at rising edges after settling; raw ready outputs can have brief internal-transfer transients.

Interface and legal requests

inputs:  clk, rst, push, pop, write_data[width-1:0]
outputs: empty, full, read_data[width-1:0]

There is no debug interface and no additional external handshake. Reset is active high and asynchronous. The oldest word is visible on read_data when not empty. A consumer captures that old word on the rising edge where it requests pop.

pop  → !empty
push → (!full || pop)

As in the preceding proposal, the caller must obey these valid-FIFO rules. The supplied RTL advances pointers even for invalid requests; a 40105 does not reproduce that behavior. Empty pop, including push+pop while empty, is outside the equivalence claim. read_data while empty is unspecified. Simultaneous push+pop while full is supported.

One external period per transaction

Clock eventAction
clk ↑Consumer samples the old head and flags. Input registers capture push, pop and write_data. SI goes low and SO goes high to rearm the FIFO inputs.
clk = 1Captured requests and data settle; no FIFO operation starts.
clk ↓SI rises for a captured push; SO falls for a captured pop. Both may occur in this clock period.
clk = 0Internal data movement and ready flags settle before the next rising edge.
Next clk ↑The next request is accepted immediately, including another push. No idle cycle is inserted.
on clk ↑: {D_hold, W, R} ← {write_data, push, pop}
rst = 1: {D_hold, W, R} ← 0

W_n = !W
R_n = !R
SI  = NOR(clk, W_n)       // LOW during clk HIGH
P   = NOR(clk, R_n)
SO  = !P                 // HIGH during clk HIGH

DIR_ALL = DIR_L & DIR_H   // one chip: DIR_ALL = DIR
DOR_ALL = DOR_L & DOR_H   // one chip: DOR_ALL = DOR
full  = !DIR_ALL
empty = !DOR_ALL

Implement the strobe gates with clk directly on a NOR input. At a rising edge, the high clock masks the strobe before the newly captured W/R values propagate. At the falling edge, W/R have already been stable for half a period. Do not substitute an independently delayed inverted-clock branch feeding AND gates without analyzing its overlap with the register updates.

The captured data remain unchanged through the low half-period. Changing external requests or data after the rising-edge setup/hold window cannot create extra transfers. Holding push high across several rising edges produces one write in each following low half-period.

At full with push=pop=1: hold SI high during the low half-period. If SI arrives before SO, the FIFO waits for space; when the pop creates a vacancy, the held write is accepted. If SO arrives first, SI subsequently writes into the available space. The data must stay stable until that internal transfer completes. This is why a narrow edge pulse is not assumed.

DIR and DOR recover after internal transfers even while SI remains high or SO remains low. They are not simply inverses of those strobes. This behavior and the held-write-at-full case are described by TI, functional description and Figure 13.

Reset clears W/R and the input data registers and invalidates the FIFO contents. With W=R=0, SI=0 and SO=1 for either clock level. Hold reset until these levels have settled before releasing it, and meet the register reset-recovery requirement relative to clk. No ARM or transfer button is needed.

Timing limits of the one-clock interface

T_HIGH > register clk→Q + request inversion + FIFO data setup
T_LOW  > strobe logic + FIFO settling + downstream logic + receiver setup

Also satisfy minimum SI/SO high and low pulse widths, data hold, clock skew and reset timing. A full simultaneous read/write needs enough low time for the vacancy to reach the input and for the held write to complete before D_hold changes at the next rising edge. This is a half-cycle timing path, not a multi-cycle transaction.

For the selected HC FIFO at 4.5 V, TI lists full-temperature minimum SI high/low widths of 24 ns, SO widths of 36 ns, and data hold of 38 ns; SO-to-DIR ripple can take 750 ns. These are individual-device values, not a maximum frequency for the whole breadboard. Retain a slow assembled-clock setting until the complete timing paths are checked on the actual build.

The unchanged original RTL is instantiated at depth 16 with debug outputs unconnected. Tests check every rising-edge observation and the settled result after the falling edge against an independent queue. They cover consecutive transfers without idle clocks, the requested six-cycle example, fill/drain, one-word simultaneous transfer, replacement at full, input changes after capture, reset during activity and 2,000 random valid cycles per configuration. The three 8-bit runs vary the SI/SO ordering.

This is behavioral verification, not a physical build or vendor timing simulation. The device model now includes ready recovery independent of the held strobe and a pending write at full. The earlier model tied ready to the whole strobe duration; that conservative model was unsuitable for evaluating this direct-clock adapter and has been replaced. Electrical skew, minimum-delay paths and all timing margins still need bench verification.
