40105 FIFO implementations:
Codex versus Claude

Reviewed 18 October 2026 · Authored by Codex · Local design files, source inspection and rerun simulations

Codex’s current single-FIFO design uses fewer chips and has more complete assembly documents. Claude’s synchronous proposal has stronger simulation coverage, handles empty-FIFO button requests more predictably, and includes a working simulation of the three-FIFO adder.

Both now use the same basic clocking scheme and can process requests in consecutive clock periods. Neither has been demonstrated on physical hardware. This compares the actual saved designs, including my shortcomings, rather than making a general claim about either AI system.

“Equivalent to the RTL” needs a precise boundary

The requested RTL module increments its write pointer whenever push is high and its read pointer whenever pop is high. It does not internally reject requests using empty/full. My original tests therefore restrict stimulus to valid queue operations: no pop while empty, and no push while full unless accompanied by a pop.

Claude’s tests compile that same module unchanged, but drive it through an additional request filter:

accepted_pop  = pop  & !empty;
accepted_push = push & (!full | accepted_pop);

This defines a useful protected interface for student buttons. It is not unconditional equivalence to the raw module for the same push/pop inputs. It also differs from the lab’s default push & !full wiring, which rejects a full push even when pop is asserted. The lab comments describe permitting replacement as an alternative.

These distinctions were reproduced in a new directed test with both raw and guarded RTL references; see its log. An invalid empty pop is not evidence that the raw RTL is defective. Conversely, calling it invalid does not make my unguarded circuit a good unrestricted button interface.

Claude’s criticism of my empty push/pop behavior is valid. The important correction to its comparison is how that finding is described: it exposes a robustness gap against a protected interface, rather than disproving the narrower valid-transaction contract I tested. My original tests did not cover this practical button-use case.

In the models, SI can load the new word before SO removes it. Which action reaches the output first determines whether the word survives. The TI description confirms independent SI/SO operation and that a write held at full can be accepted after unloading creates space. It does not establish a safe timing order for this unguarded empty push/pop sequence. TI CD74HC40105 functional description.

Simulation strengths and limits

My model uses ideal input registers, two aggregate strobe delays and an abstract queue. The wiring is checked separately for connectivity and Boolean behavior. That does not simulate the timing of the drawn chip netlist.

Claude models individual packages and the FIFO’s internal ripple, checks stored contents as well as head/flags, and exercises bounce, resets, boundary requests and deliberately faulty circuits. Its copied Codex netlist is a useful additional check, but ties D3 low. The shared cross-comparison therefore does not test all sixteen possible input words.

Both sets of chip models are handwritten, not vendor-certified. Claude’s five corners are selected delay assumptions, not an exhaustive sweep of manufacturing, voltage, temperature and loading. Bounce simulation also does not model analog metastability. Statements such as “cannot glitch whatever the delays” or “hold time met by construction” still need actual timing bounds.

For example, Claude’s P3 relies on the sum remaining valid long enough after C’s SI edge, while A/B begin to pop through another gate. That is a minimum-delay/hold-time question; making the overall clock slower does not prove it. At 4.5 V, TI lists SO-to-DIR maximum ripple delays of 500 ns at 25°C and 750 ns across −55…125°C. Those figures are compatible, but neither is a complete breadboard frequency guarantee. TI switching specifications; NOR specifications; register specifications.

The three-FIFO adder: Claude is further along

Claude has the stronger deliverable for teaching a synchronous FIFO adder today. However, its shared three-bit input and full-input acceptance policy are material differences from my independent four-bit valid/ready exercise. Neither “P3” label nor a common FIFO chip makes the two interfaces identical.

Cost and readiness to assemble

The common October 14 component-price snapshot gives $2.92 for Codex’s four single-FIFO ICs and $3.32 for Claude’s five. The difference is $0.40, about 12% of Claude’s IC subtotal. These are historical planning figures, not current supplier quotes or complete-kit prices.

Codex’s advantage

One 830-contact breadboard; 50 specified on-board jumpers: 33 signals, 11 IC power connections and six rail links. External module and supply leads are additional. The placement picture shows power wires and signal labels; the schedule supplies every signal connection.

Static checks cover all 60 DIP pins, net separation, unique hole use, power continuity and gate logic. The drawings and timing diagram are available in both languages and both image formats.

Claude’s advantage

Its synchronous kit B includes the parts for BB8 and P3: $37.80 component subtotal, $50.91 landed estimate, $81.99 classroom and $112.99 suggested retail. These are the saved proposal’s prices, covering a broader kit than a single FIFO.

Synchronous wiring remains estimated at about 50 jumpers for BB8 and 113 for P3. The older, routed variant A cannot be used unchanged to build variant B.

My kit inventory is inconsistent with my newer proposal. The single-FIFO CSV still lists 40105 + 4081 + 4069, omitting the 40174 and 4001 used by the four-chip circuit. Its $18.58 component total is therefore not a priced BOM for that circuit. Use the proposal’s four-IC list for comparison; do not present the older kit as ready to purchase for this implementation.

The strongest next single-FIFO design combines both

For a four-bit student FIFO, use Codex’s compact package allocation and assembly documentation, with Claude’s proposed empty-pop guard. Claude already demonstrated this combination in its hybrid netlist; I reproduced its five-corner pass. The idea and gate reassignment below are Claude’s contribution.

U4.E:  pin 11 ← DOR;  pin 10 → empty = !DOR
U4.F:  pin 13 ← pop;  pin 12 → pop_n = !pop
U3.D:  pins 12,13 ← pop_n, empty; pin 11 → pop_ok
U2:    pin 14 (D6) ← pop_ok, replacing raw pop

pop_ok = NOR(pop_n, empty) = pop & DOR

This reuses the two spare 4069 inverters and the NOR previously used to make empty, so the IC count stays four and the historical IC subtotal stays $2.92. It intentionally adopts the protected request semantics described above. The input setup budget must include the new pop-qualification path.

This is a recommended revision, not the present breadboard wiring. Its pin diagram, jumper schedule and kit BOM must be updated, and its comparison should be extended to all four input bits. The existing 50-jumper total is not a count for the hybrid. Physical timing and indicator loading still need checking on a prototype.

For the three-FIFO adder, Claude’s synchronous P3 is the better starting point. First choose whether to retain its shared three-bit controls or implement independent four-bit operands, and whether full input queues should accept a replacement. That interface choice determines the comparison reference.
