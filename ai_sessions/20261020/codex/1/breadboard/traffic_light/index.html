1. Exercise BB-FSM-01 · Timofei’s traffic light

A traffic light is a useful first finite state machine (FSM): the outputs depend on a stored state, and each clock edge advances that state. Here the repeating sequence is red → yellow → green → red. Red occupies four states, yellow two and green four.

This follows Timofei Nikiforov’s idea described in Yuri Panchul’s course. The same “state register + output decoding” structure appears in peripheral controllers, protocol sequencers and processor control logic. This exercise teaches the link between a breadboard circuit and synthesizable RTL.

Prerequisites: breadboard power rails, reading DIP pin numbers, OR gates and clock edges. The supplied circuit is a teaching sequence; intersection coordination and pedestrian inputs are outside this exercise.

2. The state machine and OR logic

S0 → S1 → S2 → S3 → S4 → S5 → S6 → S7 → S8 → S9 → S0

red    = S0 | S1 | S2 | S3
yellow = S4 | S5
green  = S6 | S7 | S8 | S9

S0–S9 are names of states and decoded signals, not chip pin numbers. At a settled state exactly one S signal is high. The source’s “outputs 1–4, 5–6, 7–10” uses one-based counting; this lesson consistently uses the datasheet’s Q0–Q9 naming.

For a four-input OR, 0000 gives 0; each of the other fifteen input combinations gives 1. Reset is asynchronous and active high: it selects S0 immediately, even between clock edges. Normal counting uses rising clock edges only.

At clock frequency f, the durations are 4/f, 2/f and 4/f seconds. The diagram places reset at t=0 and the first counting edge at t=1 s. Releasing a real asynchronous reset at an arbitrary time can shorten the first red interval; complete subsequent cycles still have the 4/2/4 ratio.

4. CMOS chips: functions, pins and polarity

U1 CD4017BE: cycles through Q0…Q9. CLOCK pin 14 advances on a rising edge when INHIBIT pin 13 is low. RESET pin 15 is high-active and overrides counting. Pin 12 is a carry output, high in S0…S4 and low in S5…S9; it is unused here.

The second clock input has an important detail: lowering INHIBIT while CLOCK is high also advances the counter. We tie INHIBIT permanently to GND. The chip model and its unit test cover this behavior; the lesson’s top-level interface needs only clk and rst. TI reference; 4017-family clock truth table.

U2 CD4072BE: two four-input OR gates. Inputs 2,3,4,5 → output 1 (red); inputs 9,10,11,12 → output 13 (green). U3 CD4071BE: four two-input OR gates. Inputs 1,2 → output 3 (yellow). All logic outputs used here are active high. TI OR-gate datasheet.

6. Schematic 2 · Chip connections

red is U2.1, yellow is U3.3, green is U2.13. Connect each to the anode of its corresponding current-limited indicator; connect cathodes to common GND. Clock, reset and supply modules share that ground.

7. Schematic 3 · Breadboard assembly

Insert all DIP packages across the central trench with notches upward: U1 in rows 8–15, U2 in 22–28, U3 in 35–41. Pin 1 occupies column e at the first row; the opposite top pin is in column f. Within a row, a–e are connected and f–j are connected; the two halves are separate.

LP/LM are the left positive/ground rails; RP/RM are the right rails. Rail holes are numbered 01–50 from top to bottom independently of the 63 terminal rows. The drawing assumes a break between rail holes 25 and 26 and bridges all four rails. Inspect the continuity of your actual board before applying this numbering.

8. Generic synthesizable SystemVerilog

Both designs have exactly the same interface: clk, rst → red, yellow, green, state[9:0]. The generic design uses a one-hot state register, so the three equations match schematic 1 directly. Reset is required before normal operation.

Generic RTL — full source

rtl/traffic_light.sv

`timescale 1ns/1ps
`default_nettype none
// Synthesizable generic FSM. State is a one-hot vector, not a decimal pin number.
module traffic_light (
    input  wire       clk,
    input  wire       rst,       // asynchronous, active high; reset selects S0
    output wire       red,
    output wire       yellow,
    output wire       green,
    output reg  [9:0] state
);
    always @(posedge clk or posedge rst)
        if (rst)
            state <= 10'b0000000001;
        else
            state <= {state[8:0], state[9]};

    assign red    = |state[3:0];
    assign yellow = |state[5:4];
    assign green  = |state[9:6];
endmodule
`default_nettype wire

SystemVerilog describes concurrent hardware: the register remembers a state, while all three output equations are continuously active. The shift concatenation rotates the one-hot marker, not software instructions. The real 4017 uses a five-stage Johnson counter internally; functional equivalence does not require identical internal storage.

9. SystemVerilog models of the CMOS chips

All three models are synthesizable functional models with logical ports named after chip pins. Physical VDD/VSS and NC pins are documented in the diagram, not modeled as HDL power pins. There are no propagation delays. They do not verify LED current, supply quality, metastability or electrical pulse limits.

cd4017b.sv

models/cd4017b.sv

`timescale 1ns/1ps
`default_nettype none
// Synthesizable, zero-delay FUNCTIONAL model of a powered CD4017B.
// VDD pin 16 and VSS pin 8 are physical supply connections, not HDL ports.
// Binary encoding is an abstraction of the chip's five-stage Johnson counter.
// Requires reset; does not model illegal Johnson states, power-up, drive current,
// setup/hold, pulse width, propagation delay or analog glitches.
// The effective-clock expression also captures a falling INHIBIT edge while
// CLOCK is high. In the exercise INHIBIT is permanently tied low, so synthesis
// removes this gate. Do not use changing combinational clock gates in FPGA RTL.
module cd4017b (
    input  wire p14_clock,
    input  wire p13_inhibit,
    input  wire p15_reset,
    output wire p3_q0, p2_q1, p4_q2, p7_q3, p10_q4,
    output wire p1_q5, p5_q6, p6_q7, p9_q8, p11_q9,
    output wire p12_carry
);
    wire effective_clock = p14_clock & ~p13_inhibit;
    reg [3:0] count;
    always @(posedge effective_clock or posedge p15_reset)
        if (p15_reset)
            count <= 4'd0;
        else if (count == 4'd9)
            count <= 4'd0;
        else
            count <= count + 4'd1;

    assign p3_q0  = count == 4'd0;
    assign p2_q1  = count == 4'd1;
    assign p4_q2  = count == 4'd2;
    assign p7_q3  = count == 4'd3;
    assign p10_q4 = count == 4'd4;
    assign p1_q5  = count == 4'd5;
    assign p5_q6  = count == 4'd6;
    assign p6_q7  = count == 4'd7;
    assign p9_q8  = count == 4'd8;
    assign p11_q9 = count == 4'd9;
    assign p12_carry = count < 4'd5;
endmodule
`default_nettype wire

The 4017 model uses a binary counter as an abstraction and matches the legal reset/count sequence, including carry and inhibit. It does not implement the physical Johnson counter’s recovery from illegal internal codes. In this exercise inhibit is tied low, allowing synthesis to remove the effective-clock gate.

11. Testbenches and simulator scripts

The testbench compares both implementations with an independent expected state and expected lamp pattern. Equality alone is insufficient: two wrong designs could agree. Checks cover 12 complete cycles, 529 observations, asynchronous reset at both clock levels, held reset, falling-edge stability and wrap from S9 to S0.

Main equivalence testbench

tb/tb_traffic_light.sv

`timescale 1ns/1ps
`default_nettype none
// Simulation only. Portable procedural checks; no classes, DPI or UVM.
module tb_traffic_light;
    reg clk = 1'b0;
    reg rst = 1'b0;
    wire r0,y0,g0,r1,y1,g1;
    wire [9:0] s0,s1;
    integer expected = 0;
    integer checks = 0;
    integer visits [0:9];
    integer red_slots = 0, yellow_slots = 0, green_slots = 0;
    integer i,round;
    traffic_light generic_dut(clk,rst,r0,y0,g0,s0);
    traffic_light_chips chip_dut(clk,rst,r1,y1,g1,s1);

    task check_state;
        reg [9:0] wanted;
        reg [2:0] lamps;
        begin
            wanted = 10'b1 << expected;
            if (expected < 4) lamps=3'b100;
            else if (expected < 6) lamps=3'b010;
            else lamps=3'b001;
            if (s0 !== wanted || s1 !== wanted || {r0,y0,g0} !== lamps || {r1,y1,g1} !== lamps)
                $fatal(1,"state=%0d generic=%b/%b chips=%b/%b",expected,s0,{r0,y0,g0},s1,{r1,y1,g1});
            checks=checks+1;
        end
    endtask
    task pulse;
        begin
            #4; clk=1'b1;
            expected=rst ? 0 : (expected+1)%10;
            #1; check_state();
            #4; clk=1'b0;
            #1; check_state(); // no advance on the falling edge
        end
    endtask
    task reset_at_current_level;
        begin
            #2; rst=1'b1; expected=0;
            #1; check_state(); // reset does not wait for a clock edge
            #2; rst=1'b0;
            #1; check_state();
        end
    endtask
    initial begin
        $dumpfile("traffic_light.vcd");
        $dumpvars(0,tb_traffic_light);
        for(i=0;i<10;i=i+1) visits[i]=0;
        reset_at_current_level();
        for(round=0;round<12;round=round+1)
            for(i=0;i<10;i=i+1) begin
                visits[expected]=visits[expected]+1;
                if(r0) red_slots=red_slots+1;
                if(y0) yellow_slots=yellow_slots+1;
                if(g0) green_slots=green_slots+1;
                pulse();
            end
        if(red_slots!=48 || yellow_slots!=24 || green_slots!=48)
            $fatal(1,"4/2/4 duration mismatch");
        for(i=0;i<10;i=i+1)
            if(visits[i]!=12) $fatal(1,"missing state %0d",i);
        // Asynchronous reset from every reachable state, at both clock levels.
        for(round=0;round<2;round=round+1)
            for(i=0;i<10;i=i+1) begin
                reset_at_current_level(); clk=1'b0;
                repeat(i) pulse();
                if(round==1) begin clk=1'b1; expected=(expected+1)%10; #1; end
                reset_at_current_level(); clk=1'b0; #1; check_state();
            end
        rst=1'b1; expected=0; #1;
        repeat(3) pulse(); // reset dominates the clock
        rst=1'b0; #1; check_state();
        $display("PASS traffic_light: %0d checks; 12 full cycles; red/yellow/green=48/24/48; reset and wrap",checks);
        $finish;
    end
    initial begin #100000; $fatal(1,"timeout"); end
endmodule
`default_nettype wire

`timescale 1ns/1ps
`default_nettype none
module tb_cmos;
    reg [7:0] a=0;
    wire [3:0] or2;
    wire [1:0] or4;
    reg clk=0, inhibit=0, rst=0;
    wire [9:0] q;
    wire carry;
    integer i,expected=0;
    cd4071b g2(a[0],a[1],a[2],a[3],a[4],a[5],a[6],a[7],or2[0],or2[1],or2[2],or2[3]);
    cd4072b g4(a[0],a[1],a[2],a[3],or4[0],a[4],a[5],a[6],a[7],or4[1]);
    cd4017b counter(clk,inhibit,rst,q[0],q[1],q[2],q[3],q[4],q[5],q[6],q[7],q[8],q[9],carry);
    task check_counter;
        begin
            #1;
            if(q!==(10'b1<<expected) || carry!==(expected<5))
                $fatal(1,"4017 state/carry mismatch: expected=%0d q=%b carry=%b",expected,q,carry);
        end
    endtask
    initial begin
        for(i=0;i<256;i=i+1) begin
            a=8'(i); #1;
            if(or2 !== {(|a[7:6]),(|a[5:4]),(|a[3:2]),(|a[1:0])} || or4 !== {(|a[7:4]),(|a[3:0])})
                $fatal(1,"OR pin truth-table mismatch input=%h",a);
        end
        rst=1;expected=0;check_counter();rst=0;
        for(i=0;i<30;i=i+1) begin
            #2;clk=1;expected=(expected+1)%10;check_counter();
            #2;clk=0;check_counter();
        end
        inhibit=1;
        repeat(4) begin #2;clk=1;check_counter();#2;clk=0;check_counter();end
        // Releasing inhibit when CLOCK is low is not a count event.
        inhibit=0;check_counter();
        // A rising clock counts; raising inhibit while clock is high does not.
        clk=1;expected=1;check_counter();inhibit=1;check_counter();
        // Falling inhibit while CLOCK is high counts according to the chip function.
        inhibit=0;expected=2;check_counter();
        rst=1;expected=0;check_counter();inhibit=1;clk=0;check_counter();
        clk=1;check_counter();inhibit=0;check_counter(); // reset dominates both clock inputs
        $display("PASS CMOS: 256 OR input combinations; 30 count edges; carry, inhibit and asynchronous reset");
        $finish;
    end
endmodule

                    $fatal(1,"Tiny Tapeout output mismatch state=%0d model=%0d",n,j);
            end
        end
    endtask
    initial begin
        seven[0]=8'h3f;seven[1]=8'h06;seven[2]=8'h5b;seven[3]=8'h4f;seven[4]=8'h66;
        seven[5]=8'h6d;seven[6]=8'h7d;seven[7]=8'h07;seven[8]=8'h7f;seven[9]=8'h6f;
        #2;rst=1;check_all();rst=0;check_all();
        for(i=0;i<30;i=i+1) begin
            ui=0;check_all();ui=1;check_all();ena=0;check_all();ena=1;
            #4;clk=1;n=(n+1)%10;check_all();#4;clk=0;check_all();
        end
        // BGM's key[0] is a reset button. TT uses its dedicated rst_n.
        key=1;rst=1;n=0;check_all();key=0;rst=0;check_all();
        $display("PASS integrations: both implementations in BGM lab/hackathon and Tiny Tapeout; 30 steps, both display modes, ena and reset");
        $finish;
    end
endmodule

14. Integration with Tiny Tapeout project.v

The supplied project.v uses the requested Tiny Tapeout port interface with the unique top name tt_um_timofei_traffic_light. rst_n is active low, so the core receives ~rst_n. Configure the project’s external clock to 1 Hz; this wrapper does not divide a MHz clock.

Port / RP2350Assignment
clk / GPIO16; rst_n / GPIO14Clock and reset; select the project, assert reset, then run the clock.
ui_in[0] / GPIO17DIP 0: 0 = lamp-position bars, 1 = state number 0…9. Other DIP inputs unused.
uo_out[7:0] / GPIO40…33{dp, g, f, e, d, c, b, a} · active high
uio_out[2:0] / GPIO27…25{green, yellow, red}
uio_oe[7:0]00000111 when ena=1; otherwise all pins are inputs.
enaProject-mux enable, not a board pin. Blanks outputs and disables bidirectional drivers when 0; it does not pause the state counter.

In bar mode, segment a (top) means red, g (middle) means yellow and d (bottom) means green; the display itself does not change LED color. In decimal mode it shows the state number, not a countdown. The standard mapping above differs from BGM’s abcdefgh[7:0] bit order. Keep the RP2350 pins connected to uio[2:0] configured as inputs when this project drives them.

// Synthesizable Tiny Tapeout top. Set the EXTERNAL project clock to 1 Hz.
// Default USE_CHIP_MODEL=0; set to 1 to synthesize the pin-connected version.
module tt_um_timofei_traffic_light # (parameter USE_CHIP_MODEL=0) (
    input  wire [7:0] ui_in,
    output wire [7:0] uo_out,
    input  wire [7:0] uio_in,
    output wire [7:0] uio_out,
    output wire [7:0] uio_oe,
    input  wire       ena,
    input  wire       clk,
    input  wire       rst_n
);
    wire red,yellow,green;
    wire [9:0] state;
    generate
        if(USE_CHIP_MODEL==0) begin : generic_version
            traffic_light dut(clk,~rst_n,red,yellow,green,state);
        end else begin : chip_version
            traffic_light_chips dut(clk,~rst_n,red,yellow,green,state);
        end
    endgenerate
    // TT output order [7:0] = {dp,g,f,e,d,c,b,a}; active high.
    // DIP 0 = 0: top/middle/bottom bar represents red/yellow/green.
    // DIP 0 = 1: show state number 0..9, not the number of seconds remaining.
    reg [7:0] decimal_segments;
    always @* begin
        case(state)
            10'b0000000001: decimal_segments=8'h3f;
            10'b0000000010: decimal_segments=8'h06;
            10'b0000000100: decimal_segments=8'h5b;
            10'b0000001000: decimal_segments=8'h4f;
            10'b0000010000: decimal_segments=8'h66;
            10'b0000100000: decimal_segments=8'h6d;
            10'b0001000000: decimal_segments=8'h7d;
            10'b0010000000: decimal_segments=8'h07;
            10'b0100000000: decimal_segments=8'h7f;
            10'b1000000000: decimal_segments=8'h6f;
            default: decimal_segments=8'h00;
        endcase
    end
    wire [7:0] bars={1'b0,yellow,2'b00,green,2'b00,red};
    assign uo_out=ena ? (ui_in[0] ? decimal_segments : bars) : 8'b0;
    assign uio_out=ena ? {5'b0,green,yellow,red} : 8'b0;
    assign uio_oe=ena ? 8'b00000111 : 8'b0;
    wire unused_inputs=&{1'b0,ui_in[7:1],uio_in};
endmodule

15. Bring-up, experiments and sources

  1. With power disconnected, install chips and all 37 jumpers. Check notch orientation, power pins and split rails.
  2. Connect the module leads and current-limited indicators. Verify 5 V across the rails before running the circuit.
  3. Set the assembled clock near 1 Hz. Hold RESET high: red must stay on even while the clock runs.
  4. Release reset. Observe repeating red/yellow/green intervals in the ratio 4/2/4. Time a complete cycle after the initial reset interval.
  5. Run the testbenches. Then try either implementation in the supplied FPGA or ASIC wrapper.
ObservationCheck
Always redRESET stuck high, no clock edges, or U1.13 not at GND.
Only one color missingLED polarity, OR output pin and the corresponding Q inputs.
Wrong duration / skipped colorConfusing state numbers with physical pins; use the state-to-pin table.
Dim lamps or unstable behaviorMeasured supply voltage, common ground, module loading and defined input levels. Static HDL simulation cannot diagnose these.

Try next: change the grouping to 3/3/4; predict the truth table before rewiring. Explain why connecting Q outputs directly together is not OR. Compare one-hot RTL with a binary 0…9 counter plus a decoder. Investigate the distinction between a short gate-delay transient and an incorrect stable state.

The drawings and zero-delay models describe settled logic. Real outputs have propagation delays; this exercise does not prove hazard-free lamp transitions. The assembled clock is reused as supplied by the course: students do not build a clock oscillator here.
